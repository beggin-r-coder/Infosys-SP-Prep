## 🧩 PROBLEM SOLVING PATTERNS

</div>

| # | Pattern | When to Use | Complexity |
|---|---------|-------------|------------|
| 01 | **Sliding Window** | Subarray/substring problems | `O(n)` |
| 02 | **Two Pointers** | Sorted arrays, palindrome checks | `O(n)` |
| 03 | **Fast & Slow Pointers** | Cycle detection in linked lists | `O(n)` |
| 04 | **Binary Search** | Sorted data, minimize/maximize | `O(log n)` |
| 05 | **BFS / Level Order** | Shortest path, graph traversal | `O(V+E)` |
| 06 | **DFS + Backtracking** | Permutations, combinations, mazes | `O(n!)` |
| 07 | **Dynamic Programming** | Overlapping subproblems | `O(n²)` |
| 08 | **Monotonic Stack** | Next greater/smaller element | `O(n)` |
| 09 | **Union-Find (DSU)** | Connected components, Kruskal's | `O(α(n))` |
| 10 | **Topological Sort** | Task scheduling, course prereqs | `O(V+E)` |

## 💡 PRO TIPS FOR SP EXAM

</div>

> 🧠 **Think out loud on paper** — Draw the approach before coding

> ⏱️ **Time box aggressively** — 60 min max per problem; partial credit exists

> 🎯 **Brute force first** — Then optimize. A working O(n²) > broken O(n log n)

> 🔎 **Edge cases are everything** — Empty input, single element, negatives, duplicates

> 📦 **Know your STL/Collections** — HashMap, PriorityQueue, TreeMap save time

> 💬 **Comment your logic** — Evaluators read your code; clarity matters
